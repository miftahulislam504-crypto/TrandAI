# Phase 1: Daraz MVP

লক্ষ্য: Daraz থেকে প্রতিদিন ৪৫০টার মতো প্রোডাক্টের স্ন্যাপশট (দাম, রেটিং, রিভিউ সংখ্যা, সোল্ড) Supabase-এ জমানো এবং ড্যাশবোর্ডে দেখা। ট্যাগ (Best/Mid/Don't) আসবে Phase 2-এ।

## ১. যা বানানো হয়েছে

| অংশ | কী করে |
|---|---|
| `scrapers/common/http.py` | ভদ্র HTTP ক্লায়েন্ট: রিকোয়েস্টের মাঝে বিরতি, robots.txt মানে, ব্লক ধরলে নিজে থেমে যায় |
| `scrapers/daraz/` | Daraz parser ও adapter (লিস্টিং, প্রোডাক্ট পেজ, রিভিউ) |
| `scrapers/run_daraz.py` | মূল রান: `--smoke`, `--dry-run`, বা পুরো রান |
| `supabase/migrations/…phase1.sql` | ড্যাশবোর্ডের ভিউ `listing_overview` ও ১:১ canonical product ফাংশন |
| `dashboard/` | Next.js ড্যাশবোর্ড: তালিকা, ফিল্টার, প্রোডাক্ট ডিটেইল, গ্রাফ। পাসওয়ার্ড দিয়ে সুরক্ষিত |
| `.github/workflows/daraz-smoke.yml` | ডাটাবেজ ছাড়া পরীক্ষা: কী ফিল্ড আসছে |
| `.github/workflows/daraz-daily.yml` | প্রতিদিন রাত ২:০০ (বাংলাদেশ) স্বয়ংক্রিয় রান |

## ২. কীভাবে কাজ করে

1. **ডিসকভারি:** `config/daraz.json`-এর seed (সার্চ শব্দ বা ক্যাটাগরি URL) ধরে লিস্টিং পেজ থেকে প্রোডাক্ট তালিকা আনে। লিস্টিংয়েই দাম, রেটিং, রিভিউ ও সোল্ড থাকার কথা, তাই প্রতিটা প্রোডাক্ট পেজ আলাদা করে খুলতে হয় না। এতে রিকোয়েস্ট ও GitHub মিনিট অনেক কম লাগে (দিনে প্রায় ১০০–১২০টা রিকোয়েস্ট, ১০ মিনিটের মতো)।
2. **কৌশল:** আগে `ajax=true` JSON, না পেলে পেজের HTML-এ এমবেডেড `window.pageData`। যেটা কাজ করে সেটাই বাকি পেজে চলে।
3. **স্ন্যাপশট:** প্রতিদিনের (বাংলাদেশ তারিখ) একটা সারি প্রতি প্রোডাক্টে। একই দিনে আবার চালালে মার্জ হয়, ডুপ্লিকেট হয় না।
4. **ডিটেইল:** নতুন বা ব্র্যান্ড-হীন সর্বোচ্চ ৩০টা প্রোডাক্টের পেজ খুলে ফাঁকা ঘর ভরে।
5. **রিভিউ:** যেগুলোর রিভিউ সংখ্যা বেড়েছে (সর্বোচ্চ ২০টা) তাদের নতুন রিভিউ আনে। রিভিউয়ারের নাম সেভ হয় না, শুধু হ্যাশ।
6. **নিরাপত্তা ব্রেক:** টানা ৩বার ব্লক বা রেট-লিমিট পেলে রান থেমে যায় এবং `scrape_runs`-এ `partial` লেখা হয়। সাইটকে চাপ দেওয়া হয় না।
7. **নিষ্ক্রিয়:** ৩০ দিন তালিকায় না এলে `is_active = false`।

## ৩. চালু করার ধাপ

**ধাপ ১: Supabase প্রজেক্ট**
- SQL Editor-এ পরপর চালান: `20261109000000_init.sql`, তারপর `20261110000000_phase1.sql`।
- Settings → API থেকে **Project URL** ও **service_role key** নিন।

**ধাপ ২: স্মোক টেস্ট (আগে এটা, ডাটাবেজ ছাড়াই)**
- GitHub → Actions → **Daraz Smoke Test** → Run workflow।
- Summary-র রিপোর্ট আমাকে পাঠান। নিচে দেখুন কী খুঁজবেন।

**ধাপ ৩: GitHub Secrets**
- Settings → Secrets and variables → Actions: `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, আর ইচ্ছে হলে `REVIEWER_HASH_SALT` (যেকোনো র‍্যান্ডম লেখা)।

**ধাপ ৪: Dry run, তারপর আসল রান**
- Actions → **Daraz Daily** → Run workflow → `dry_run` চালু করে একবার দেখুন।
- ঠিক থাকলে `dry_run` ছাড়া একবার চালান। এরপর প্রতিদিন নিজে চলবে।

**ধাপ ৫: ড্যাশবোর্ড (Vercel)**
- `dashboard/` ফোল্ডার আলাদা রিপো বা একই রিপোর Root Directory হিসেবে Vercel-এ ডিপ্লয় করুন।
- Environment Variables: `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`, `DASHBOARD_USER`, `DASHBOARD_PASSWORD`। `NEXT_PUBLIC_` প্রিফিক্স দেবেন না।
- `DASHBOARD_PASSWORD` না দিলে ড্যাশবোর্ড কিছুই দেখায় না।

## ৪. স্মোক রিপোর্টে কী দেখবেন

| দেখুন | ভালো লক্ষণ | সমস্যা হলে |
|---|---|---|
| কৌশল `ajax` বা `html` | কোনো একটা এসেছে | `None` মানে লিস্টিং আসেনি। নোটে কারণ আছে (robots নিষেধ, ব্লক, আইটেম নেই) |
| ব্লক / robots নিষেধ | ০ | বেশি হলে সাইট স্ক্র্যাপ আটকাচ্ছে। তখন বিকল্প ঠিক করতে হবে (SOURCE_AUDIT.md ৪ নম্বর ধাপ) |
| কভারেজ: url, title, price | ~১০০% | কম হলে key-এর নাম আলাদা। আইটেমের key তালিকা দেখে `parse.KEYS` ঠিক করব |
| কভারেজ: `sold_count` | যত বেশি তত ভালো | ০% হলে লিস্টিংয়ে সোল্ড নেই। Phase 2-এ Demand রিভিউ বৃদ্ধি দিয়ে মাপা হবে |
| কভারেজ: `rating_avg` | বেশি | ০% হলে প্রোডাক্ট পেজ থেকে নেওয়া হবে |
| প্রোডাক্ট পেজ ও রিভিউ | ফিল্ড/সংখ্যা এসেছে | `error` থাকলে রিভিউ endpoint অনুমান ভুল ছিল, রিপোর্ট দেখে ঠিক করব |

## ৫. যা এখনও যাচাই হয়নি (গুরুত্বপূর্ণ)

আমার এনভায়রনমেন্ট থেকে Daraz-এ ঢোকা যায় না। তাই এগুলো **অনুমান**, স্মোক টেস্টে প্রথমবার যাচাই হবে:

- লিস্টিং JSON-এর গঠন (`mods.listItems`, `itemSoldCntShow`, `ratingScore` ইত্যাদি key)। আসল রেসপন্স আলাদা হলে `scrapers/daraz/parse.py`-এর `KEYS` তালিকা বদলালেই চলবে।
- `ajax=true` ও `sort=popularity` প্যারামিটার কাজ করে কি না।
- রিভিউ endpoint (`my.daraz.com.bd/pdp/review/getReviewList`)।
- Daraz-এর robots.txt লিস্টিং বা `ajax` পাথ নিষেধ করে কি না। করলে স্ক্র্যাপার সেটা ফেচ করবে না এবং রিপোর্টে "robots.txt নিষেধ করেছে" দেখাবে।
- GitHub-এর IP থেকে Daraz ব্লক করে কি না।
- একটা তথ্য ইতিমধ্যে দেখা গেছে: সাধারণ ফেচে Daraz-এর ক্যাটাগরি পেজে প্রোডাক্ট কার্ড নেই (শুধু পেজের কাঠামো), তাই লিস্টিং JavaScript দিয়ে লোড হয়। এই কারণেই `ajax` ও `pageData` কৌশল রাখা হয়েছে।

**যা যাচাই হয়েছে:** পার্সার, HTTP ক্লায়েন্ট (ব্লক, robots, retry), পুরো পাইপলাইন ও SQL মাইগ্রেশন নকল Daraz সার্ভার, আসল PostgreSQL ও PostgREST-এর বিরুদ্ধে চালানো হয়েছে। ড্যাশবোর্ড আসল ডেটা, লগইন ও ফিল্টার সহ পরীক্ষা হয়েছে। অর্থাৎ Daraz-এর আসল রেসপন্স মিললেই পুরো সিস্টেম চলার কথা।

## ৭. কনফিগ

- `config/daraz.json`: seed (সার্চ শব্দ/ক্যাটাগরি URL), বিরতি, পেজ সীমা, ডিটেইল ও রিভিউয়ের সীমা। ফ্যাশন ও হোমের seed আমি সাধারণ সার্চ শব্দ দিয়ে দিয়েছি, নিজের মতো বদলাবেন।
- `config/categories.json`: প্রতি ক্যাটাগরিতে কতটা প্রোডাক্ট (ফ্যাশন ১৭০, হোম ১৪০, কিচেন ১৪০)।
- প্রোডাক্ট বাড়াতে এই সংখ্যা ও seed বাড়ান।
