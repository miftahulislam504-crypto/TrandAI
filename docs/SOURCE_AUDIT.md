## ১. যা এখন পর্যন্ত দেখা গেছে

২০২৬-১১-০৯ তারিখে Daraz ও Cartup-এর একটা করে প্রোডাক্ট পেজ সাধারণ HTML ফেচে খোলা হয়েছে। নমুনা মাত্র একটা, তাই এগুলো থেকে সাধারণ সিদ্ধান্ত নেওয়া যাবে না। আসল উত্তর আসবে `probe.py`-এর রিপোর্ট থেকে।

### Daraz (একটা No Brand কিচেন আইটেম)

| দেখা গেছে | দেখা যায়নি (সাধারণ HTML ফেচে) |
|---|---|
| শিরোনাম, ব্র্যান্ড ("No Brand" সহ) | গড় স্টার রেটিং |
| বর্তমান দাম, আগের দাম, ছাড়ের % | রিভিউয়ের টেক্সট |
| "Ratings 25" (রেটিং সংখ্যা) | সোল্ড কাউন্ট |
| সেলারের নাম, Positive Seller Ratings, Ship on Time | |
| ক্যাটাগরি ব্রেডক্রাম্ব, ডেলিভারি ফি ও সময়, রিটার্ন/ওয়ারেন্টি | |

- প্রোডাক্ট URL-এর গঠন: `/products/<slug>-i<item_id>.html`। এই `item_id` হবে আমাদের `external_id`।
- যা দেখা যায়নি সেগুলো সম্ভবত পেজ লোডের পরে আলাদা অনুরোধে আসে। `targets.json`-এর `search_json_candidate` ও `reviews_json_candidate` সেই অনুমান পরীক্ষা করবে। endpoint দুটো অনুমানভিত্তিক, কাজ না করলে রিপোর্টে তাই দেখাবে।

### Daraz ক্যাটাগরি পেজ (Phase 1-এ দেখা)
- সাধারণ HTML ফেচে একটা ক্যাটাগরি পেজে (food-preparation) কোনো প্রোডাক্ট কার্ড ছিল না, শুধু হেডার-ফুটার ও পেজের কাঠামো। মানে লিস্টিং JavaScript দিয়ে লোড হয়।
- পেজের মেটাডেটায় কার্ডের ট্র্যাকিং-এ `data-item-id` ও `data-sku-simple` আছে, অর্থাৎ item id দিয়েই প্রোডাক্ট শনাক্ত হয়।
- তাই Phase 1-এর adapter লিস্টিং আনার দুটো কৌশল রেখেছে (`ajax=true` JSON, এমবেডেড `window.pageData`)। কোনটা কাজ করে তা স্মোক টেস্ট দেখাবে।

### Cartup (একটা প্রোডাক্ট)

| দেখা গেছে | দেখা যায়নি |

- বর্ণনার টেক্সটে "Daraz" শব্দটা আছে। অনুমান: বর্ণনা Daraz-এর লিস্টিং থেকে নেওয়া। এটা ঠিক হলে একই প্রোডাক্ট দুই সাইটে মেলানো সহজ হতে পারে, তবে রেটিং ও রিভিউ আলাদা।

### Facebook Ads Library
- অফিসিয়াল API ইইউ ও ইউকের বাইরে কমার্শিয়াল বিজ্ঞাপন দেয় না। ওয়েবসাইটে কমার্শিয়াল বিজ্ঞাপন দেখা যায়, কিন্তু ইম্প্রেশন বা খরচ নেই।
- Phase 6-এ আধা-ম্যানুয়াল পদ্ধতি দিয়ে শুরু হবে। এই ZIP-এর probe এটা পরীক্ষা করে না (পেজ JavaScript-নির্ভর)।

### ফলব্যাক: তৃতীয়-পক্ষ Daraz স্ক্র্যাপার
Apify-তে Daraz-এর জন্য তৃতীয়-পক্ষের স্ক্র্যাপার আছে। তালিকা অনুযায়ী দাম প্রতি ১,০০০ ফলাফলে প্রায় $0.69। আউটপুটে দাম, ব্র্যান্ড, সেলার ও রেটিং স্কোর দেখা গেছে, সোল্ড কাউন্টের উল্লেখ দেখা যায়নি। নিজের স্ক্র্যাপার ব্লক হলে এটা বিকল্প, তবে এতে সাইটের শর্তের প্রশ্ন নিজে থেকে মেটে না।

### প্ল্যাটফর্মের তালিকা

## ২. probe রিপোর্ট কীভাবে পড়বেন

| কলাম | মানে |
|---|---|
| **HTTP** | 200 = পেজ এসেছে। 403/429/503 = ব্লক বা রেট লিমিট |
| **robots** | `allowed` = অনুমতি আছে। `disallowed` = সাইট নিষেধ করেছে, probe তাই ফেচই করেনি। `unknown` = robots.txt আনা যায়নি |
| **বট সিগন্যাল** | captcha ইত্যাদি মার্কার পাওয়া গেছে কি না। মার্কার থাকলেই ব্লক নয়: HTTP কোড, ছোট বডি বা "Access Denied"/"Just a moment" টাইটেল দেখে সিদ্ধান্ত নিন |
| **সোল্ড / রেটিং** | পেজ বা JSON-এ ওই ধরনের key বা টেক্সট আছে কি না |

বিস্তারিত অংশে দেখবেন:
- **JSON-LD / `__NEXT_DATA__` / স্টেট মার্কার:** ডেটা পেজের ভেতরেই এমবেডেড কি না। থাকলে স্ক্র্যাপিং সহজ।
- **আইটেম তালিকার key:** JSON endpoint কাজ করলে প্রতিটা আইটেমে কী কী ফিল্ড আছে।
- **`sold` key:** সোল্ড কাউন্টের সম্ভাব্য ফিল্ডের নাম। `soldOut` ধরনের key বাদ দেওয়া হয়।

## ৪. robots ও ToS সিদ্ধান্তের ধাপ

1. robots.txt যা নিষেধ করে, স্ক্র্যাপার তা করবে না। probe-ও তা মানে।
2. প্রতিটা সাইটের Terms পড়ে স্ক্র্যাপিং বা অটোমেটেড অ্যাক্সেস নিয়ে ধারা খুঁজুন।
3. নিষেধ থাকলে অফিসিয়াল API, পার্টনারশিপ বা ডেটা প্রোভাইডার দেখুন। না হলে ওই সোর্স বাদ।
4. যেগুলো চলবে সেগুলোতে: ধীর রিকোয়েস্ট, লগইনের পেছনে না যাওয়া, ব্যক্তিগত তথ্য (রিভিউয়ারের নাম) না রাখা।
5. এটা আইনি পরামর্শ নয়। ঝুঁকি বেশি মনে হলে আইনজীবীর পরামর্শ নিন।
